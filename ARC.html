Theory

The sensor bar reads reflectance across the front of the robot. Each sensor has a signed position from the bar’s center, and the line position is the weighted average of those positions. Zero means centered; positive means the line is to the right.

u(t) = Kp·e(t) + Ki·∫e(t)dt + Kd·de(t)/dt

The correction u turns the robot toward the line. P reacts to the present offset, I removes a steady bias, and D damps fast changes.

Algorithm

  1. Read every sensor at a fixed interval.
  2. Compute the weighted line position, normalized to −1…1.
  3. If every sensor loses the line, hold the last error.
  4. Update the integral and derivative with the same time step.
  5. Clamp the correction, set steering, and move the robot.

Arduino version

float integral = 0, previousError = 0;

void controlStep(float dt) {
  float error = readWeightedLinePosition();
  integral = constrain(integral + error * dt, -2, 2);
  float derivative = (error - previousError) / dt;
  float correction = kp * error + ki * integral + kd * derivative;

  setMotorSpeeds(baseSpeed + correction, baseSpeed - correction);
  previousError = error;
}

Keep the loop interval steady. A variable delay changes the I and D terms even when the gains stay the same.

FAQ

Why does the robot weave along the line?

P is too high, D is too low, or the speed is too high for the sensor layout. Lower speed first, then tune P and D.

How many sensors should I use?

Five is a good start. Three works at low speed, and eight or nine help at higher speed.

Will these gains work on real hardware?

Use them as a starting point. Real robots have motor deadband, wheel slip, lighting changes and loop jitter, so re-tune after calibrating your sensors.
